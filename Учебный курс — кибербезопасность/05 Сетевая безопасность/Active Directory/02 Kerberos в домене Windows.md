# Kerberos в домене Windows

Kerberos использует доверенный Key Distribution Center на контроллере домена и билеты вместо передачи пароля каждому сервису.

## Упрощённый поток

1. Клиент проходит первичную проверку и получает Ticket Granting Ticket — TGT.
2. С TGT он запрашивает у Ticket Granting Service билет для конкретного SPN.
3. Клиент предъявляет service ticket сервису.
4. Сервис проверяет билет своим ключом; при необходимости выполняется взаимная аутентификация.

**SPN** связывает экземпляр сервиса с доменной учётной записью. Время важно: значительный рассинхрон может нарушить проверку билетов.

## Риски и причины

- Kerberoasting использует возможность запросить service ticket и проверять его офлайн; риск усиливают слабые пароли сервисных учётных записей.
- AS-REP roasting возможен для учётных записей без обязательной pre-authentication.
- небезопасное делегирование расширяет возможность действовать от имени пользователя;
- кража ключевого материала позволяет подделывать или повторно использовать удостоверения.

Защита строится на gMSA или длинных случайных секретах сервисов, современной криптографии, контроле делегирования, привилегий и событий KDC. Сам факт запроса билета не доказывает атаку — нужен контекст.

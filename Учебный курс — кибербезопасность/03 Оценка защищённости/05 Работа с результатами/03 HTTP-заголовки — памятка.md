# HTTP-заголовки — памятка

> [!note] Проверка источников завершена
> Базовая линия: OWASP Secure Headers. Исторические payload-примеры ниже сохранены для разбора, но не считаются рекомендацией для реальных систем; практику выполняйте только в назначенной лаборатории внешней учебной платформы и в пределах её правил.

> [!note] Статус материала
> Исходный конспект сохранён, но команды, версии, зависимости и внешние ссылки необходимо сверять с официальной документацией перед практикой.

## Входные заголовки и доверие proxy

Клиент способен самостоятельно отправить почти любой request header. Поэтому следующие значения нельзя считать доказательством адреса или происхождения запроса без контролируемой цепочки proxy:

1. `X-Forwarded-For` — цепочка адресов, которую trusted reverse proxy должен очистить и сформировать по политике;
2. `True-Client-IP` — нестандартный заголовок, смысл задаёт конкретный proxy/CDN;
3. `Referer` — URL предыдущей страницы, который может отсутствовать, сокращаться политикой или подделываться небраузерным клиентом;
4. `X-WAP-Profile` — исторический указатель на профиль устройства; не является доверенным признаком клиента.

Если приложение напрямую доступно в обход proxy или доверяет первому значению `X-Forwarded-For`, злоумышленник может повлиять на IP-based ограничения и журналы. Проверяют список trusted proxies, перезапись заголовков на границе и способ получения адреса framework.

## Основные защитные response headers

| Заголовок | Назначение | Что проверять |
| --- | --- | --- |
| `Strict-Transport-Security` | требует HTTPS для будущих обращений | применяется только после корректного HTTPS; параметры и поддомены соответствуют архитектуре |
| `Content-Security-Policy` | ограничивает источники ресурсов и другие возможности документа | политика фактически ограничивает опасные источники; отсутствие `unsafe-*` оценивается в контексте |
| `X-Content-Type-Options: nosniff` | запрещает часть MIME-sniffing | корректные `Content-Type` должны быть заданы сервером |
| CSP `frame-ancestors` | управляет встраиванием страницы во frame | политика покрывает чувствительные страницы и нужных партнёров |
| `Referrer-Policy` | ограничивает данные в `Referer` | выбран баланс приватности и бизнес-интеграций |
| `Permissions-Policy` | ограничивает browser features | директивы соответствуют реально используемым функциям |

`X-Frame-Options` остаётся совместимым legacy-механизмом для frame protection, но современная гибкая политика задаётся через CSP `frame-ancestors`. Один отсутствующий заголовок не всегда является отдельной уязвимостью: нужно показать применимый сценарий, существующие эквивалентные меры и затронутый ресурс.

## Cookies и кэширование

Для session cookie оценивают `Secure`, `HttpOnly`, `SameSite`, область `Domain`/`Path` и срок жизни. Для чувствительных ответов проверяют допустимость хранения в browser и shared caches через `Cache-Control`. Флаги cookie уменьшают отдельные риски, но не исправляют слабую серверную авторизацию.

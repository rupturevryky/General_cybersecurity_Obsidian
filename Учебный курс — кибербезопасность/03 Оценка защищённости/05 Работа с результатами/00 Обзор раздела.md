# Работа с результатами

Сырой вывод инструмента становится находкой только после проверки применимости, влияния и затронутых активов. Хороший отчёт позволяет владельцу воспроизвести проблему, принять решение и проверить исправление без догадок.

Памятка заголовков — справочник для интерпретации, а не checklist, где отсутствие каждого заголовка автоматически является уязвимостью.

## Жизненный цикл находки

`кандидат → верификация → оценка риска → согласование → исправление → retest → закрытие/принятие риска`.

Retest проверяет конкретное исправление и отсутствие очевидной регрессии в пределах согласованного scope. Он не равен новой полной оценке. Если исправление изменило архитектуру или поверхность, требуется расширенная проверка.

## Качество рекомендации

Рекомендация устраняет root cause или разрывает сценарий, имеет владельца и проверяемый критерий. «Обновить всё», «настроить firewall» или «санитизировать ввод» недостаточны без компонента, безопасного состояния и способа проверки.

## Внешняя практика

Возьмите подтверждённую находку из внешней платформы, оформите её по шаблону, затем напишите retest-план с положительной, отрицательной и регрессионной проверкой.

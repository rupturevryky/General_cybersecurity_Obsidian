# Ошибки памяти и защитные механизмы

Memory safety bug возникает, когда программа неверно обращается с границами, временем жизни или типом объекта.

## Основные классы

- out-of-bounds read/write;
- stack или heap buffer overflow;
- use-after-free и double free;
- integer overflow, приводящий к неверному размеру;
- format string vulnerability;
- uninitialized memory и type confusion.

Crash доказывает нарушение доступности в конкретных условиях, но не автоматически выполнение кода. Для более сильного вывода нужно установить контролируемые данные, повреждённый объект, достижимость управления и влияние защит.

## Mitigations

- NX/DEP запрещает исполнение страниц данных;
- ASLR рандомизирует расположение областей;
- stack canary обнаруживает часть перезаписей перед возвратом;
- PIE позволяет рандомизировать основной модуль;
- RELRO ограничивает изменение таблиц динамического связывания;
- CFI ограничивает допустимые переходы управления;
- sandbox уменьшает последствия компрометации процесса.

Наличие mitigation не устраняет ошибку, а отсутствие — не доказывает готовый exploit. Проверяйте фактический бинарный файл, окружение и архитектуру.

## Внешняя практика

Решайте только назначенные PWN-задачи pwn.college, Hack The Box или аналогичной платформы.

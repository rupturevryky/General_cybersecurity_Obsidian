# Журналы и аудит Linux

Журналирование должно позволять восстановить последовательность действий, но не должно сохранять пароли, токены и лишние персональные данные.

## Источники событий

- systemd journal и syslog-сервисы — сообщения ядра, служб и приложений;
- auth-журналы — входы, sudo и ошибки аутентификации;
- `auditd` — правила аудита системных вызовов и изменений критичных объектов;
- application logs — события бизнес- и прикладного уровня.

Полезные команды чтения:

```bash
journalctl -u ssh --since today
journalctl -p warning..alert
ausearch -m USER_LOGIN -ts today
```

Имена unit и наличие `auditd` зависят от дистрибутива. Удалённая централизованная доставка повышает сохранность доказательств при компрометации узла.

## Требования к событию

Время в UTC или с явным часовым поясом, стабильный идентификатор узла, субъект, действие, объект, результат и correlation ID. Синхронизация времени критична для сопоставления событий между системами.

## На собеседовании

Объясните различие обычного application log и Linux Audit, а также почему indiscriminate command-line logging может раскрыть секреты.

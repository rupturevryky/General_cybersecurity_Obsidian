# STRIDE и сценарии угроз

STRIDE — подсказка для систематического просмотра элементов модели:

| Категория | Вопрос |
| --- | --- |
| Spoofing | может ли субъект выдать себя за другого? |
| Tampering | можно ли незаметно изменить данные или код? |
| Repudiation | сможет ли субъект отрицать действие из-за слабых доказательств? |
| Information Disclosure | могут ли данные попасть не тому субъекту? |
| Denial of Service | можно ли лишить систему доступности? |
| Elevation of Privilege | можно ли получить лишние полномочия? |

STRIDE не является рейтингом и не заменяет понимание бизнеса. Не каждую категорию нужно механически назначать каждому объекту.

## Хороший сценарий угрозы

Формат: субъект с возможностями выполняет действие через поверхность, что приводит к влиянию на актив при заданных условиях.

> Злоумышленник с украденным refresh token повторно получает access token через endpoint обновления, потому что токен не ротируется, и сохраняет доступ к данным после смены пароля.

Сценарий проверяем: видны предпосылка, путь, слабость и влияние. Фраза «возможен взлом API» бесполезна.

## Abuse cases

Обычный use case описывает желаемое действие, abuse case — намеренное или ошибочное использование. Проверяйте обход последовательности, повтор операции, конкурентные запросы, массовое потребление ресурса, действия привилегированного инсайдера и отказ внешней зависимости.

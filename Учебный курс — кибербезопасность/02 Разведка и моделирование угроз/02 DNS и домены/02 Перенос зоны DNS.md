# Перенос зоны DNS

**Zone transfer** синхронизирует данные между авторитетными DNS-серверами. AXFR передаёт полную зону, IXFR — изменения. Успешный AXFR постороннему клиенту может раскрыть внутренние имена и структуру, но сам по себе не даёт контроль над ними.

Проверка является активным взаимодействием с сервером и выполняется только для явно разрешённого домена и его авторитетных NS.

> [!note] Явная проверка AXFR
> Запрос переноса зоны выполняется к конкретному авторитетному DNS-серверу. Отказ в AXFR — ожидаемое безопасное поведение. Проверяйте только принадлежащую организации зону или учебный DNS-сервер.

```bash
dig AXFR example.test @ns1.example.test
host -l example.test ns1.example.test
```

> [!note] Статус материала
> Исходный конспект сохранён, но команды, версии, зависимости и внешние ссылки необходимо сверять с официальной документацией перед практикой.

Успешность этой операции основана на неправильной конфигурировании **DNS**-серверов системными администраторами (если внешнюю зону забыли отделить от внутренней). В этом случае мы можем просто запросить у серверов передачу и получим целиком зону — то есть узнаем все доменные имена. Сделать это можно двумя утилитами: **host** и [dnsrecon](https://github.com/darkoperator/dnsrecon "dnsrecon").

Для утилиты **host** потребуется уже известный **NS**-сервер ([[Учебный курс — кибербезопасность/02 Разведка и моделирование угроз/02 DNS и домены/00 DNS-записи и nslookup#Получение адреса NS|Получение адреса NS]]). Вводим команду:
```
host -l alg*******ge.com ns3.alg*******ge.com
```
Чтобы воспользоваться **dnsrecon**, нужно ввести:
```
dnsrecon -d alg*******ge.com -t axfr
```
Отказ означает только то, что конкретный сервер не передал конкретную зону этому клиенту в момент проверки. Он не доказывает корректность всей DNS-архитектуры.

Стандарт протокола: [RFC 5936 — DNS Zone Transfer Protocol](https://www.rfc-editor.org/rfc/rfc5936.html).

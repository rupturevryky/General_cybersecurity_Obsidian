# Протоколы удалённого доступа

Удалённый доступ означает управление системой, командной оболочкой, рабочим столом, файлами или службой через сеть. До подключения нужно знать адрес, транспортный порт, протокол, способ аутентификации и ожидаемую идентичность сервера.

| Задача | Типичный протокол | Что получает пользователь |
| --- | --- | --- |
| командная оболочка Linux/Unix | SSH | текстовую сессию и туннели |
| графический рабочий стол Windows | RDP | удалённый интерактивный сеанс |
| сетевые файлы Windows | SMB | общие ресурсы и именованные каналы |
| защищённая передача поверх SSH | SFTP/SCP | операции с файлами |

Аутентификация отвечает «кто подключается», авторизация — «что ему разрешено». Шифрование защищает канал, но не исправляет слабый пароль или чрезмерные права. При первом SSH-подключении проверяют host key; при RDP — сертификат и имя; при SMB — доверенный сервер и домен.

Команды ниже допустимы только для своей системы или назначенной внешней лаборатории. Наличие доступного порта не является разрешением на вход.

## SMB
Протокол удалённого подключения к файловой системе и её управления на Windows. В рамка CTF и работы с уязвимостями на Linux используется утилита `smbmap`

---

### SMBMAP

узнать подробнее о службе SMB на хосте: 
```
smbmap -H {TARGET_IP}
```

---

###  SMBCLIENT

узнать подробнее о службе SMB на хосте:  
```shell-session
smbclient -L {TARGET_IP} -U {USER_NAME}
```
```shell-session
smbclient -N -L \\\\{TARGET_IP}\\
```
- `-L` : просмотр служб, которые есть на сервере
- `-U` : имя пользователя
- `-N` : No password 


 2. чтобы войти к какую-то службу от корневой 
	 ```
	smbclient -N \\\\{TARGET_IP}\\<some share>
	```

---

### SMBGET

`smbget -R smb://10.10.1.2/<Disk>` - скачать доступный ресурс рекурсивно
Альтернативный способ:
``` 
mkdir Shares 
cd Shares 
smbclient //192.168.2.4/Docs 

smb: \> recurse on 
smb: \> prompt off 
smb: \> mget *
```

---

### SMBCLIENT-NG

Github: [p0dalirius/smbclient-ng](https://github.com/p0dalirius/smbclient-ng)
Быстрый и удобный способ взаимодействия с общими ресурсами SMB.

Пример:
``` shell
./smbclient-ng.py -d "LAB" -u "Administrator" -p 'Admin123!' --host "10.0.0.201"
```

CrackMapExec — историческое название проекта. Актуальное поддерживаемое продолжение называется NetExec (`nxc`). Старые команды нельзя переносить механически: сверяйте `nxc --help`, протокол, модуль и разрешённый scope. NetExec способен не только читать состояние, но и аутентифицироваться, выполнять команды и изменять удалённые системы.

## SSH
чтобы подключиться:
``` 
ssh <login>@<ip-address> -p <port>
```
подключиться без пароля по ssh ключу:
```
ssh -i <key_file> <login>@<ip-address>
```
#### SCP
Позволяет передать файл на удалённый сервер или скачать его с удалённого сервера.
Пример передачи в папку /tmp:
```
scp <file> <ssh_login>@<IP>:/tmp
```
Пример скачивания файла:
``` 
scp <ssh_login>@<IP>:<path_to_file> .
```

## Redis
in-memory database. Для взаимодействия используется утилита `redis-cli`
пример:
```bash
redis-cli -h <hostname> #подключение к хосту

info # получить информацию находясь на хосте

SELECT <> # выбрать данные, например SELECT 0 - узнать ключи под индексом 0

keys * # узнать, какие ключи есть в БД

get <key> # получить значение ключа <key>

```

## Важное разграничение

Redis и MySQL — сетевые службы данных, а не протоколы удалённого администрирования общего назначения. Их клиент даёт только права, предусмотренные конкретной СУБД. Пароль не передают прямо в аргументах команды: он может попасть в историю и список процессов; используйте интерактивный запрос или защищённый механизм конфигурации клиента.

SMB, SSH и RDP требуют проверки идентичности сервера, индивидуальной аутентификации, минимальных прав и журналирования. Устаревшие незашифрованные протоколы удалённого входа, например Telnet, не используют для административного доступа.

Утилиты перечисления и Impacket могут выполнять действия за пределами простого подключения. Перед каждым запуском определите сетевые запросы, используемые credentials и допустимость модуля в scope.

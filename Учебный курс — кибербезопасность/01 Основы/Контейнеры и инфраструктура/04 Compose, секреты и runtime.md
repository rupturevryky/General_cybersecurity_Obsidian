# Compose, секреты и runtime

Compose описывает набор сервисов, сетей, volumes и параметров запуска. Это удобная декларация среды, но не отдельная граница безопасности.

## Секреты и конфигурация

Переменная окружения удобна, но доступна процессу и часто попадает в диагностику. `.env` нельзя считать секретным хранилищем. Секреты передают штатным механизмом платформы как ограниченно доступные файлы или краткоживущие учётные данные, исключают из репозитория и регулярно ротируют.

```bash
docker compose config
docker compose ps
docker compose logs --since 10m service
docker inspect container
```

`docker compose config` показывает итоговую конфигурацию после подстановок и может раскрыть секреты; обращайтесь с выводом как с чувствительными данными.

## Runtime baseline

- не использовать `privileged`, если нет строго доказанной необходимости;
- не монтировать Docker socket в контейнер;
- сокращать Linux capabilities и запрещать повышение привилегий;
- root filesystem делать read-only, writable-данные выносить отдельно;
- ограничивать CPU, память, процессы и log growth;
- публиковать только необходимые порты и разделять сети;
- не монтировать корень хоста и чувствительные каталоги;
- задавать healthcheck как сигнал работоспособности, не как доказательство безопасности.

Доступ к Docker daemon фактически даёт административный контроль над хостом: можно запустить привилегированный контейнер или смонтировать host filesystem.

## Диагностический порядок

Сначала `docker compose ps`, затем события и журналы конкретного сервиса, итоговая конфигурация, mounts/networks и ресурсы. Перезапуск без сбора состояния может скрыть причину.

## Внешняя практика

В назначенном контейнерном модуле внешней платформы проведите review предоставленного Compose-файла: секреты, порты, сети, volumes, capabilities, пользователь и лимиты. Предложите минимальные изменения без локального развёртывания.

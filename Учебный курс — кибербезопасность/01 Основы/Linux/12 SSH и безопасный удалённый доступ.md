# SSH и безопасный удалённый доступ

**SSH** защищает удалённую командную сессию, передачу файлов и туннели. Сервер доказывает свою идентичность host key, клиент — паролем, пользовательским ключом или другим разрешённым способом. Шифрование канала не компенсирует украденную учётную запись или ошибочную авторизацию.

## Host key и known_hosts

При первом соединении клиент ещё не знает ключ сервера. Fingerprint нужно сверить по независимому доверенному каналу. Запись в `~/.ssh/known_hosts` помогает обнаружить неожиданную смену ключа. Не удаляйте предупреждение автоматически: смена может быть штатной переустановкой, ошибкой DNS или атакой посредника.

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
ssh-keygen -F server.example
ssh -vv user@server.example
```

## Пользовательские ключи

Публичный ключ размещают на сервере в `~/.ssh/authorized_keys`; закрытый остаётся у клиента и защищается правами и парольной фразой. Агент хранит разблокированный ключ в памяти, поэтому доступ к его сокету чувствителен.

```bash
ssh-keygen -t ed25519 -a 64
ssh-add -l
stat -c '%A %U:%G %n' ~/.ssh ~/.ssh/authorized_keys
```

Ключ — не «вход без аутентификации». Сервер проверяет доказательство владения закрытым ключом и ограничения записи `authorized_keys`, например `from=`, `command=` или запрет forwarding.

## Эффективная конфигурация сервера

```bash
sudo sshd -t
sudo sshd -T
sudo sshd -T -C user=alice,host=server,addr=192.0.2.10
systemctl status ssh
journalctl -u ssh --since today
```

`sshd -t` проверяет синтаксис, `sshd -T` показывает итоговые значения с учётом include; блоки `Match` могут менять результат для конкретного клиента. Имя unit и путь журнала различаются между дистрибутивами.

Практичный baseline: запрет прямого входа root, ключи для администрирования, ограниченный список пользователей/групп, отключение ненужных forwarding-функций, своевременные обновления и наблюдение за входами. Отключать парольную аутентификацию следует только после проверки рабочего резервного доступа.

## Туннели и риски

- `-L` открывает локальный порт к ресурсу через сервер;
- `-R` делает порт доступным со стороны удалённого сервера;
- `-D` создаёт динамический SOCKS-прокси;
- agent forwarding позволяет удалённому узлу обращаться к локальному агенту и увеличивает доверие к нему.

Туннель может обходить ожидаемую сетевую сегментацию. Разрешайте только необходимое и учитывайте в мониторинге.

## Внешняя практика

В разрешённой лаборатории изучите эффективную конфигурацию SSH и события входа. Найдите минимум три настройки, влияющие на поверхность атаки, и обоснуйте изменение. Не меняйте доступ, пока задание явно этого не требует.

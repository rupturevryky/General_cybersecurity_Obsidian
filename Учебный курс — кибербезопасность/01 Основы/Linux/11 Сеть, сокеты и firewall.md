# Сеть, сокеты и firewall

Этот урок переносит общие понятия из [[Учебный курс — кибербезопасность/01 Основы/Сети/00 Обзор раздела|сетевых основ]] на Linux. **Интерфейс** связывает систему с сетью, **маршрут** выбирает следующий узел, **сокет** представляет конечную точку обмена, а firewall принимает решение о прохождении пакета по правилам.

## Последовательность диагностики

```bash
ip -brief link
ip -brief address
ip route
ip route get 1.1.1.1
ip neighbor
resolvectl status
ss -lntup
```

Проверяйте по слоям: интерфейс поднят → адрес и префикс корректны → есть маршрут → работает разрешение имён → процесс слушает ожидаемый адрес и порт → firewall допускает трафик → приложение отвечает. `ping` проверяет только часть пути и может блокироваться.

`127.0.0.1:8080` доступен только локально. `0.0.0.0:8080` означает прослушивание всех IPv4-адресов, но не гарантирует доступ извне: остаются firewall, маршрутизация и внешняя фильтрация. Для IPv6 смысл привязки и dual-stack поведения зависит от приложения и системы.

## Соединения и процессы

```bash
ss -lntup                    # слушающие TCP/UDP-сокеты
ss -tnp state established    # установленные TCP-соединения
lsof -nP -iTCP -sTCP:LISTEN
curl -v --connect-timeout 5 http://127.0.0.1:8080/
```

Для вывода владельца чужого процесса могут потребоваться повышенные права. Не делайте вывод о вредоносности только по внешнему IP: установите процесс, пользователя, время, назначение узла и DNS-контекст.

## Firewall

Современная подсистема ядра — netfilter; правила обычно управляются через `nftables`. `iptables` может быть совместимым интерфейсом поверх nftables или отдельным legacy backend. `ufw` и `firewalld` — более высокоуровневые средства. Не смешивайте их без понимания, кто владеет итоговым ruleset.

Безопасный аудит начинается с просмотра:

```bash
sudo nft list ruleset
sudo ufw status verbose
sudo firewall-cmd --state
sudo firewall-cmd --list-all
```

Не выполняйте очистку правил на удалённом сервере: можно потерять доступ и открыть сервисы. При изменении заранее обеспечивают разрешение текущей административной сессии, резервный канал и откат.

## Захват трафика

```bash
sudo tcpdump -ni any 'host 192.0.2.10 and (tcp port 443 or udp port 53)'
```

`tcpdump` подтверждает наличие пакетов, направления, флаги и тайминги. Шифрованный payload он не раскрывает. Захват может содержать персональные данные и токены; выполняйте его только с разрешением и храните ограниченно.

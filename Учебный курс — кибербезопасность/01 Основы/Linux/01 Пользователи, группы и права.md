# Пользователи, группы и права доступа

Linux проверяет доступ по числовым идентификаторам UID и GID. Имя пользователя — удобное отображение UID. У процесса есть эффективный пользователь и группы; именно их ядро сравнивает с владельцем и правами файла.

Обычная модель доступа содержит владельца, группу и остальных пользователей. `root` обладает особыми полномочиями, но процессы root всё равно оставляют следы и могут быть ограничены дополнительными механизмами вроде SELinux, AppArmor, namespaces и capabilities.

Основные источники сведений:

```bash
id                    # UID, основная и дополнительные группы
whoami                # эффективное имя пользователя
getent passwd имя     # запись пользователя из настроенных источников
getent group группа   # состав группы
ls -l файл            # владелец, группа и базовые права
```

Домашний каталог хранит пользовательские данные и конфигурацию, но учётная запись и каталог — разные объекты. Удаление одного не всегда автоматически удаляет другое.

> [!abstract] Цель
> Научиться создавать и удалять учётные записи, управлять группами, паролями, владельцами и разрешениями файлов.

---

## Создание пользователей

```bash  
useradd [опции] пользователь
```
- `-b` - базовый каталог для размещения домашней директории пользователя, по умолчанию **`/home`**.
- `-d` - Домашний каталог, в котором буду размешаться файлы пользователя.
- `-c` - комментарий к учётной записи.
- `-e` - дата, когда учётная запись будет заблокирована.
- `-f` - заблокировать учётную запись сразу после создания.
- `-g` - основная группа пользователя.

---

## Удаление пользователей
```bash
userdel [опции] пользователь
```
- `-f` - Принудительное удаление учётной записи и домашнего каталога пользователя, даже если он ещё находится в системе.
- `-r` - Удалить пользователя вместе с домашним каталогом и почтовым ящиком.
\
---

## Смена пароля
```bash
passwd [опции] пользователь
```
- `-d` - удалить пароль пользователя (после этого он не сможет войти).
- `-e` - сделать пароль устаревшим.
- `i` - количество дней после того, как пароль устарел, по истечению которых пользователь не сможет войти в аккаунт, если не сменил пароль. 
- `l` - запретить пользователю входить в системы.
- `-n` - минимальное количество дней между сменами пароля.
- `-m` - максимальное количество дней, пока пароль можно использовать.

## Права доступа

Строка `-rwxr-x---` читается слева направо: тип объекта, затем по три права владельца, группы и остальных. Для обычного файла `r` разрешает чтение, `w` — изменение, `x` — выполнение. Для каталога `r` разрешает читать список имён, `w` — создавать и удалять записи, `x` — проходить через каталог и обращаться к объектам внутри.

Числовая запись складывает `r=4`, `w=2`, `x=1`: `750` означает `rwxr-x---`. Права родительского каталога способны запретить доступ даже к файлу с разрешающим режимом. Дополнительные ACL показываются через `getfacl`; символ `+` после режима в `ls -l` часто указывает на их наличие.

![[Учебный курс — кибербезопасность/01 Основы/Linux/assets/Pasted image 20240714131049.png]]
Первый символ указывает на тип файла:  
- `d` - директория, 
- `-` обычный файл 
- `l` - символическая ссылка 
- `c` - устройство символьного ввода/вывода
- `b` - устройство блочного ввода/вывода
- `p` - FIFO - связь между процессами
- `s` - сокет

### Изменение прав доступа

**Изменить владельца:** назначить **`user`** владельцем **`file`** 
```bash
chown [опции] user file
```

**Изменить группу на `group` для `file`:** 
```bash
chgrp [опции] group file
```

**Изменить права доступа `rwx`:**
```bash
chmod [права] file
```
![[Учебный курс — кибербезопасность/01 Основы/Linux/assets/Pasted image 20240714132121.png]]
`$ chmod a+x file` — Сделать файл исполняемым для владельца, группы и остальных
`$ chmod ug+w file` — Разрешить изменение файла для владельца и группы
`$ chmod o-w file` — Запретить запись остальным пользователям
`$ chmod ugo+rwx file` — Разрешить чтение, запись и исполнение для всех

## Группы

- Посмотреть группу - `$ sudo groups [имя пользователя]`
- Изменить группу на **`group1`** для файла **`file1`** - `$ chgrp [опции] group1 file1`
- Добавить пользователя в дополнительную группу — `$ usermod -aG [имя группы] [имя пользователя]`
  
  Для того, чтобы пользователь мог выполнять команды от имени суперпользователя, его нужно добавить в группу “`sudo`”:
  ```bash
  $ usermod -aG sudo имя_пользователя
  ```
  - `-a` - add
  - `-G` - если у пользователя уже были группы, они не отключатся от него

	Либо можно изменить файл `/etc/sudoers`
	![[Учебный курс — кибербезопасность/01 Основы/Linux/assets/Pasted image 20240714134115.png]]
	- `root ALL = (ALL:ALL) ALL` Данная строчка указывает на то, что пользователь root имеет неограниченные привилегии в системе
	- `%sudo ALL = (ALL:ALL) ALL` Пользователи в группе sudo имеют права на запуск любой программы
	  ![[Учебный курс — кибербезопасность/01 Основы/Linux/assets/Pasted image 20240714134318.png]]

## Что важно для безопасности

`r`, `w` и `x` имеют разный смысл для файла и каталога. Для каталога `r` разрешает читать список имён, `w` — создавать и удалять записи, `x` — проходить по пути. Поэтому право удаления файла в первую очередь определяется правами каталога, а не самого файла.

```bash
id alice
namei -l /path/to/file
getfacl /path/to/file
sudo -l -U alice
find / -xdev -type f -perm -4000 -ls 2>/dev/null
getcap -r / 2>/dev/null
```

ACL добавляет правила для отдельных пользователей и групп поверх базовых mode bits. SUID/SGID и Linux capabilities позволяют исполняемому файлу получить дополнительные возможности; их наличие сверяют с пакетным эталоном и baseline. `sudoers` редактируют через `visudo`, который проверяет синтаксис. Перед выдачей прав уточняют, какие конкретно команды нужны, с какими аргументами и от чьего имени.

## Внешняя практика

На разрешённой машине внешней платформы объясните эффективный доступ выбранного пользователя к файлу с помощью `id`, `namei` и `getfacl`. Найдите один SUID-файл или capability и проверьте его происхождение, не изменяя права.

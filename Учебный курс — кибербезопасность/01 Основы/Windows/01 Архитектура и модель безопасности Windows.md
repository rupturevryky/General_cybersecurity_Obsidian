# Архитектура и модель безопасности Windows

> [!abstract] Результат
> Ученик различает user mode и kernel mode, процесс и поток, объект и handle, сеанс и рабочий стол, понимает назначение UAC и уровней целостности.

## Карта системы

Windows состоит из ядра, драйверов, системных процессов, служб, пользовательских приложений и средств управления. Для ИБ важно не запоминать все компоненты, а понимать границы доверия и контекст выполнения.

**Kernel mode** имеет доступ к ядру и устройствам. Ошибка драйвера способна нарушить работу всей системы. **User mode** изолирует приложения: обычный процесс не должен напрямую читать память другого процесса или обращаться к устройству без проверки ядра.

Переход в kernel mode выполняется через системные вызовы. Это не означает, что приложение «становится ядром»: ядро проверяет параметры и выполняет разрешённую операцию от его имени.

## Процесс, поток и память

Программа на диске — файл. После запуска появляется **процесс**: контейнер ресурсов с PID, виртуальным адресным пространством, handles и primary access token. Код фактически выполняют **потоки**. У процесса как минимум один поток, но может быть много.

Виртуальная память создаёт для каждого процесса отдельное адресное пространство. Одинаковый виртуальный адрес в двух процессах не обязан указывать на одну физическую область. Общая память возможна, но создаётся явно.

При анализе процесса фиксируют:

- полный путь и цифровую подпись файла;
- командную строку;
- PID и родительский PID;
- пользователя, token и integrity level;
- время запуска;
- загруженные модули;
- сетевые соединения;
- дочерние процессы.

Одного имени `svchost.exe` или `powershell.exe` недостаточно для вывода.

## Объекты и handles

Windows представляет процессы, потоки, файлы, ключи реестра, события и другие ресурсы как объекты. **Handle** — выданная процессу ссылка на объект с определёнными правами доступа. Число handle имеет смысл только внутри соответствующего процесса.

Проверка доступа происходит при открытии объекта. Если процесс получил handle с правом чтения, последующие операции используют уже выданный доступ. Поэтому при расследовании важны открытые handles и момент их получения.

## Сеансы, станции и рабочие столы

Интерактивный вход создаёт logon session. Несколько пользователей и служебных контекстов могут одновременно иметь разные сеансы. RDP создаёт или подключает удалённый интерактивный сеанс. Session 0 изолирован для служб.

Не следует считать, что процесс, видимый в диспетчере задач, работает в том же сеансе и видит тот же рабочий стол, что текущий пользователь.

## Системные каталоги и WOW64

- `%SystemRoot%` обычно указывает на `C:\Windows`.
- `System32` на 64-битной Windows содержит основные 64-битные системные файлы.
- `SysWOW64` содержит многие 32-битные компоненты совместимости.
- `%ProgramFiles%` и `%ProgramFiles(x86)%` разделяют приложения разных архитектур.
- `%ProgramData%` хранит общие данные приложений.
- `%LOCALAPPDATA%` и `%APPDATA%` относятся к профилю пользователя.

Название `SysWOW64` исторически сбивает с толку: его нельзя интерпретировать как каталог 64-битных программ.

## UAC и integrity levels

User Account Control помогает отделять обычную работу от административной. При входе члена Administrators обычно создаются стандартный и административный варианты token. Процесс запускается без повышения, пока пользователь не подтвердит elevation.

Integrity levels выражают уровень доверия, например Low, Medium, High и System. Процесс с более низким уровнем обычно не может изменять объект более высокого уровня даже при некоторых разрешениях DACL. Это Mandatory Integrity Control, дополнительный слой к обычным ACL.

UAC не является полноценной изоляцией администратора и не заменяет работу под обычной учётной записью.

## Что полезно проверить

```powershell
whoami
whoami /all
Get-Process | Select-Object -First 10 Name,Id,Path
Get-CimInstance Win32_OperatingSystem | Select-Object Caption,Version,BuildNumber,OSArchitecture
Get-CimInstance Win32_ComputerSystem | Select-Object Name,Domain,PartOfDomain
```

Команды чтения тоже могут раскрывать чувствительные сведения; результаты не публикуют без очистки.
